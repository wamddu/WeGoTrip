# 채팅 내 위치 구현 및 실행

채팅 입력창의 `+`에서 사진·투표 옆 `내 위치`를 누르면 앱 사용 중 위치 권한으로 위치를 한 번 측정한다. Google 지도 미리보기와 공유할 채팅방을 확인하고 `이 위치 보내기`를 눌러야 메시지가 저장된다. 같은 방의 수신자는 `공유 당시 위치` 카드에서 핀·측정 시각·정확도를 보고 Google 지도에서 지점을 열 수 있다.

## 서버·DB

- `LOCATION`은 기존 전체/파티 채팅 범위와 `ChatMessage` 응답을 사용한다. 지도 미리보기·전송·카드 지도 URL·작성자 철회 API를 추가했다. 채팅 이력은 `chat_location`을 조인하고, 기존 소켓은 메시지 ID 변경 신호만 전달한다.
- 전송은 `Idempotency-Key`로 중복을 막는다. `chat_message`, 좌표, 푸시 큐는 같은 트랜잭션에서 저장된다. 재시도 저장소에는 메시지 ID만 남긴다.
- 푸시에는 `위치를 공유했어요.`를 표시하고 좌표·지도 URL은 넣지 않는다. `이미지 채팅만 보기`에는 위치 카드가 포함되지 않는다.
- 프로필의 `위치 공유`를 켜야 새 위치를 측정·전송할 수 있다. 작성자가 카드의 `위치 공유 취소`를 확인하면 좌표와 정확도를 지우고 취소 안내를 남긴다. 계정 삭제 시에도 작성자의 좌표를 정리한다.
- [016-chat-location.sql](../backend/db/migrations/016-chat-location.sql)은 2026-11-07에 연결된 WeGoTrip MySQL 8.4.9 DB에 적용했다. 신규 테이블의 외래키·CHECK와 채팅 조회 조인을 확인했고, 기존 `chat_message` DDL은 동일했다. 검증용 메시지나 좌표는 연결 DB에 넣지 않았다.
- 다른 환경에 배포할 때는 서버 코드보다 먼저 그 환경의 DB에 016을 한 번 적용한다. 이미 적용한 WeGoTrip DB에서는 다시 실행할 필요가 없다.

## Google 지도 설정

신규 위치 지도는 앱 서버가 서명한 URL로 Google에서 직접 이미지를 표시한다. 기존 `GOOGLE_MAPS_API_KEY`는 서버의 장소 검색·지도 프록시에 사용되므로 위치 카드 응답에 노출하지 않는다.

1. Google Cloud에서 **Maps Static API**와 결제를 사용 설정한다.
2. 표시 전용 API 키를 발급해 **Maps Static API**만 호출할 수 있도록 제한한다. Google 이미지 URL에 포함되는 키다.
3. [Google의 URL 서명 안내](https://developers.google.com/maps/documentation/maps-static/digital-signature)에서 해당 Cloud 프로젝트의 **URL signing secret**을 확인한다. 서명 비밀은 서버에만 둔다.
4. 실행할 백엔드의 `.env` 또는 배포 환경 변수에 아래 두 항목을 추가하고 서버를 다시 시작한다. `.env`는 버전 관리에 추가하지 않는다.

```dotenv
GOOGLE_MAPS_STATIC_API_KEY=표시용_키
GOOGLE_MAPS_URL_SIGNING_SECRET=URL_서명_비밀
```

기존 지도 키와 같은 Google Cloud 프로젝트를 쓰는 경우, 프로젝트의 **unsigned 요청 한도**를 0으로 바꾸면 기존의 서명 없는 정적 지도 요청까지 실패할 수 있다. 서명 없는 요청을 차단하려면 채팅 지도용 프로젝트를 분리하는 편이 간단하다. 웹 도메인 제한은 웹 전용 키에 적용한다. 앱과 웹에서 하나의 키를 사용하는 경우에는 네이티브 요청이 웹 도메인 제한에 막히지 않도록 키·프로젝트 설정을 각각 확인한다. [Google API 키 보안 지침](https://developers.google.com/maps/api-security-best-practices)

설정이 빠진 환경에서는 위치 지도 API가 안내와 함께 `LOCATION_MAP_UNAVAILABLE`을 반환한다. 기존 텍스트·사진·투표 채팅은 사용 가능하다.

## 실행과 검증

- 웹은 HTTPS 또는 로컬 루프백에서 위치 권한을 사용할 수 있다. 외부 배포에서는 위치를 포함한 앱 API 트래픽도 HTTPS로 연결한다.
- Android/iOS에서 실제 위치를 측정하려면 `expo-location`이 포함된 새 네이티브 빌드가 필요하다. 기존 APK에 웹 번들만 바꿔서는 모듈이 추가되지 않는다. 백그라운드 위치나 동작 인식 권한을 요청하지 않는다.
- 로컬 H2 서버 테스트 158개, 프런트엔드 테스트 197개, TypeScript 검사와 Android/iOS/Web 번들 생성이 통과했다. 서버 테스트는 가짜 좌표로 방 권한, 좌표·측정 시각 보존, 미리보기, 재전송, 철회, 계정 삭제, 푸시와 트랜잭션 롤백을 검증했다.
- 격리된 두 브라우저에서 가짜 위치와 지도 이미지로 측정 취소, 파티 채팅 미리보기, 응답 유실 후 같은 키로 재전송, 수신, 이미지 필터, 공유 철회를 확인했다. Expo 설정 검사에서 사용 중 위치 권한만 포함되는 것도 확인했다.
- 최종 배포 확인: 지도 설정이 있는 서버에 새 앱을 연결하고 프로필 위치 공유를 켠다. 두 테스트 계정으로 같은 파티에서 GPS 권한 요청, 지도 표시, 전송·수신·철회를 확인한다. 실제 사용자 위치를 검증 데이터로 재사용하지 않는다.

설계 상세는 [채팅 위치 카드 구현 계획](CHAT-LOCATION-PLAN.md)을 참고한다.
