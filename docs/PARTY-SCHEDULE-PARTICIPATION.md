# 파티별 일정 참여 구간 표시

작성일: 2026-10-02

## 변경 내용

파티 일정이 전체 일정과 겹치면, 선택한 파티의 일정 화면에는 **해당 파티 일정이 우선 표시**됩니다. 공통 일정에서는 겹치는 시간을 빼고 실제로 참여하는 구간만 표시합니다. 목록과 지도 동선에 같은 계산을 적용했습니다.

**DB와 백엔드는 변경하지 않았습니다.** 저장된 일정의 시간·장소·메모도 그대로 유지하며, 프론트엔드에서 화면에 보여 줄 참여 구간을 계산합니다.

## 표시 예시

전체 일정이 **10:00~11:00**인 경우입니다.

| A파티 일정 | A파티 화면에 표시되는 일정 |
| --- | --- |
| 10:00~11:00 | A파티 일정만 표시 |
| 10:00~10:30 | A파티 일정 → 공통 일정 10:30~11:00, **중간 합류** |
| 10:30~11:00 | 공통 일정 10:00~10:30, **중간 이탈** → A파티 일정 |
| 10:15~10:45 | 공통 일정 10:00~10:15 → A파티 일정 → 공통 일정 10:45~11:00 |
| 11:00~12:00 | 공통 일정 10:00~11:00 → A파티 일정 |

공통 일정 중간에 파티 일정이 있으면 공통 일정이 여러 참여 구간으로 나뉩니다. 각 구간에 `중간 합류` 또는 `중간 이탈`과 원래 일정 시간을 안내합니다. 한 구간의 시작과 끝이 모두 잘렸다면 두 안내를 함께 표시합니다.

**전체 일정 탭은 등록된 공통 일정의 원래 시간을 표시**합니다. A파티의 별도 일정 때문에 전체 일정 원본이나 다른 파티의 참여 시간이 바뀌지는 않습니다.

## 계산 규칙

- **같은 날짜, 선택한 파티**의 별도 일정만 공통 참여 시간에서 제외합니다.
- 같은 파티의 겹치거나 맞닿은 시간은 합쳐서 계산합니다. 파티 일정 자체는 각각 유지합니다.
- 시작 시각은 포함하고 종료 시각은 제외합니다. 따라서 10:00에 끝난 일정과 10:00에 시작하는 일정은 겹치지 않습니다.
- 시간이 미정이거나 잘못된 기존 일정은 원래대로 표시합니다. 해당 파티 일정의 시간을 알 수 없으면 공통 일정에서 임의로 제외하지 않습니다.
- **0분 파티 일정**은 공통 시간을 가리지 않습니다. **0분 공통 일정**은 그 시각이 파티 일정의 시작 이상·종료 미만에 있을 때 숨깁니다.

## 목록·지도·편집 연결

| 항목 | 동작 |
| --- | --- |
| 일정 목록 | 계산된 참여 시간 순서대로 표시하고 합류·이탈 안내 추가 |
| 지도와 장소 동선 | 동일한 참여 구간으로 핀 순서와 이동 구간 계산 |
| 완전히 가려진 공통 일정 | 선택한 파티의 목록과 지도 핀에서 제외 |
| 공통 일정 재합류 | 파티 일정 이후 남은 공통 구간으로 동선 연결 |
| 구간 식별 | 원본 일정 ID·날짜·참여 시간으로 구간별 고유 키 생성 |
| 일정 편집 | 나뉜 구간을 눌러도 원본 일정 ID와 원래 시간을 사용 |

같은 일정이 두 구간으로 보이더라도 DB에 두 일정이 생기는 것은 아닙니다. 위치가 없거나 파티 일정끼리 시간이 겹치면 기존 규칙대로 이동선을 임의로 연결하지 않습니다.

## 주요 구현

- `frontend/src/domain/route.ts`: `getEffectiveAgenda` 참여 구간 계산, 구간별 키와 원래 시간 보존, 지도 동선 연결.
- `frontend/src/domain/participation.ts`: 중간 합류·이탈 안내 문구 계산.
- 일정 목록·지도·장소 동선 화면: 계산된 구간 표시와 원본 일정 편집 연결.
- `frontend/scripts/test-app.cjs`: 겹침·재합류·시간 경계·원본 보존·지도 동선 회귀 테스트.
