# 채팅 내 위치 지도 카드 구현 계획

설계 기준일: 2026-11-07. 적용 상태와 실행 방법은 [구현 및 실행 안내](CHAT-LOCATION-IMPLEMENTATION.md)를 참고한다.

기존 `TRIP-MEMBER-LOCATION-PLAN.md`의 여행별 최신 위치 공유 방식을 이 계획으로 대체한다. 사용자가 채팅의 첨부 메뉴에서 **내 위치**를 선택하고, 현재 위치를 지도에서 확인한 뒤 **이 위치 보내기**를 누르면 해당 채팅방에 위치 메시지 한 건을 남긴다.

## 1. 사용자 흐름과 화면

```text
채팅 입력창의 +
  → [사진] [투표] [내 위치]
  → 위치 공유 설정·기기 권한 확인
  → 현재 위치 한 번 측정
  → 지도 미리보기: 현재 위치 핀·측정 시각·정확도·공유 대상 채팅방
  → [다시 측정] [취소] [이 위치 보내기]
  → 선택한 채팅방에 지도 카드 전송
```

- 현재 `chat-section.tsx`의 사진·투표 아이콘 옆에 기존 `pin` 아이콘과 `내 위치` 레이블을 추가한다. 첨부 메뉴 접근성 설명도 사진·투표·내 위치로 갱신한다.
- 전체 채팅에서는 여행 전체 채팅에, 파티 채팅에서는 선택한 파티 채팅에 전송한다. 미리보기 상단에 실제 채팅방 이름을 표시한다.
- 미리보기는 모바일 모달/시트로 연다. 닫기·취소는 채팅에 아무것도 남기지 않는다. 기존 입력 중인 텍스트도 유지한다.
- 카드에는 지도, 위치 핀, `공유 당시 위치`, 측정 시각, 정확도 안내, `Google 지도에서 열기`를 표시한다. 이름과 메시지 전송 시각은 기존 채팅 행 UI를 사용한다.
- 예시 카드 문구는 `공유 당시 위치 · 14:32 측정 · 정확도 약 25m`다. 이후 이동해도 기존 카드의 좌표·측정 시각은 변하지 않는다.
- 100m보다 정확도가 낮은 결과는 `대략적인 위치예요`를 표시하고 다시 측정을 권한다. 정확도 정보가 없으면 추정 수치를 만들지 않는다.
- 지도 요청 실패 시 미리보기의 재시도와 취소를 제공한다. 지도 확인에 성공하기 전에는 전송을 활성화하지 않는다. 이미 전송한 카드의 지도 로딩이 실패하면 측정 시각·지도 열기·재시도를 남긴다.

## 2. 위치 측정과 비동기 상태

Android/iOS는 프로젝트의 Expo SDK 57에 맞는 `expo-location`을 추가하고 foreground 권한 확인 후 `getCurrentPositionAsync()`로 한 번 측정한다. 웹은 별도 어댑터에서 `navigator.geolocation.getCurrentPosition()`을 사용한다. Expo의 현재 위치 API는 단발 측정을 지원한다. [Expo SDK 57 Location](https://docs.expo.dev/versions/v57.0.0/sdk/location/)

- 기기 위치 측정과 Google 지도 표시는 별개다. 기기에서 얻은 위도·경도를 Google 지도에 핀으로 표시한다.
- 앱 실행·로그인·채팅 진입·다른 사람의 카드 열기에는 위치를 측정하지 않는다. `내 위치`와 `다시 측정`을 눌렀을 때만 측정한다.
- 백그라운드 위치 권한, 위치 감시, 주기적 전송, 이동 경로 수집은 추가하지 않는다.
- Android/iOS 권한 설명에는 `채팅에 현재 위치를 공유할 때 사용합니다`를 사용한다. 네이티브 모듈·권한 설정 추가 후 새 APK/개발 빌드가 필요하다.
- 웹 위치 권한·보안 컨텍스트를 검사한다. 웹은 `maximumAge: 0`, 측정 제한 시간 15초를 초기값으로 사용한다. 앱도 15초 후 UI 요청을 종료하고 늦게 도착한 결과를 무시한다.
- 상태는 `권한 확인 → 측정 중 → 지도 로딩 → 전송 준비 → 전송 중 → 완료/오류`로 나누고 중복 탭을 막는다.
- 채팅방 전환·화면 이탈·백그라운드 전환·로그아웃·계정 변경 시 전송 전 미리보기를 닫고 요청 세대를 무효화한다. 늦은 측정 결과로 자동 업로드하지 않는다.
- 이미 시작된 HTTP 전송은 취소만으로 서버 저장이 취소되었다고 가정하지 않는다. 응답 유실 시 기존 메시지와 멱등 키로 결과를 확인하며, 다른 방의 목록에 응답을 합치지 않는다.
- 측정 후 미리보기에서 2분이 지나면 다시 측정을 요구한다. 네이티브가 오래된 위치를 반환해도 측정 시각을 현재 시각으로 덮어쓰지 않는다.
- 거절·위치 서비스 꺼짐·시간 초과·낮은 정확도·통신 오류를 구분해 안내한다. 사용자 설정과 OS 권한은 별도로 처리한다.

## 3. 메시지 형식과 Google 지도 표시

새 메시지 종류 **`LOCATION`**을 추가한다. 화면에서는 지도 이미지가 포함된 카드로 렌더링하고 DB에는 기기에서 얻은 좌표와 측정 시각을 보관한다. Google 지도의 화면 캡처 파일을 사진 업로드 저장소에 복사하지 않는다.

Maps Static API는 위도·경도 중심점과 `markers` 파라미터를 지정해 핀이 있는 이미지를 만들 수 있다. 카드 기본 크기는 320×200, `scale=2`, `zoom=16`으로 시작하고 Google 로고·저작권 표시가 잘리지 않도록 원본 비율 전체를 보여 준다. [Maps Static API](https://developers.google.com/maps/documentation/maps-static/start)

```text
인증된 앱 → 서버에서 미리보기/메시지 접근 권한 검사
          → 서버가 제한된 파라미터로 Google 지도 URL 서명
          → 앱·웹이 Google에서 지도 이미지를 직접 표시
```

- Google 안내는 Static API 이미지의 사본 저장·재배포 대신 Google에서 직접 표시하는 방식을 설명한다. 신규 채팅 지도는 이 흐름으로 설계하고 기존 `/api/maps/image`의 이미지 프록시를 그대로 복제하지 않는다. [Google Maps FAQ](https://developers.google.com/maps/faq#tos)
- 서버에 `StaticMapSigner`를 두고 지도 URL을 만든다. 외부 URL·키·서명·임의 마커·크기·확대값을 클라이언트에서 받아 그대로 중계하지 않는다.
- 기존 서버용 Maps 키를 응답에 넣지 않는다. 직접 표시용 Maps Static API 키를 별도로 구성하고, API 제한·웹 도메인 제한 등 배포 플랫폼에 맞는 제한을 적용한다. URL 서명 비밀은 서버에만 두고 unsigned 요청 한도를 제한한다. [Google Maps 보안 지침](https://developers.google.com/maps/api-security-best-practices)
- 서명 URL에 표시용 API 키와 좌표가 포함된다는 점을 전제로 한다. Google 서명 URL을 앱 로그인 토큰이나 만료·공유 철회 수단으로 취급하지 않는다. 이미 내려받은 이미지나 복사된 링크를 회수할 수 있다고 표시하지 않는다.
- 앱 API 응답에는 `Cache-Control: no-store`를 적용한다. Google 이미지는 앱의 명시적 디스크 캐시·Cloudinary·DB에 보관하지 않고, Google 응답의 캐시 지침을 따른다.
- 전송 전 미리보기도 지도 표시를 위해 Google에 좌표가 전달된다. 다른 채팅 멤버에게는 최종 전송 이후에만 공개된다.
- API 키·과금·서명 설정은 구현 시 별도 준비 항목이다. 이번 계획에서 키 생성·설정 변경·유료 API 호출은 수행하지 않는다.
- 주소 검색이나 역지오코딩은 첫 버전에 넣지 않는다. 좌표 핀과 측정 시각만으로 동작하도록 한다.

카드의 `Google 지도에서 열기`는 저장된 좌표로 `https://www.google.com/maps/search/?api=1&query={latitude},{longitude}`를 구성한다. 앱 설치 여부에 따라 Google 지도 앱 또는 브라우저가 열린다. 새 GPS 측정은 하지 않는다. [Maps URLs](https://developers.google.com/maps/documentation/urls/get-started)

## 4. API 계약 초안

기본 경로는 기존 `/api/v1/trips/{tripId}/chat`를 사용한다. 기존 채팅과 동일하게 `partyId` 쿼리가 없으면 전체 채팅, 있으면 해당 파티 채팅이다.

| 요청 | 역할 |
| --- | --- |
| `POST /locations/preview` | 측정 좌표를 검증하고 지도 미리보기 URL 반환. 좌표 저장·메시지·푸시·소켓 이벤트 없음 |
| `POST /locations` | `LOCATION` 메시지와 좌표를 한 트랜잭션으로 저장. `Idempotency-Key` 필수 |
| 기존 `GET /messages`, `GET /messages/{id}` | 기존 이력·단건 조회에 `location` 필드 추가 |
| `GET /messages/{id}/location-map` | 메시지와 방 접근 권한을 다시 검사한 뒤 직접 표시용 서명 지도 URL 반환 |
| `DELETE /messages/{id}/location` | 작성자가 해당 카드의 좌표 공개를 철회. 메시지는 철회 안내로 유지 |

미리보기·전송 입력은 같은 형태를 사용한다.

```json
{
  "latitude": 37.5665,
  "longitude": 126.9780,
  "accuracyM": 25.0,
  "capturedAt": "2026-11-07T05:32:00.000Z"
}
```

위 좌표는 계약 설명용 예시다. 실제 위치는 이번 작업에서 수집하지 않는다.

- 클라이언트는 작성자 ID, 지도 이미지 URL, Google 키를 전송하지 않는다. 작성자는 JWT에서 정한다.
- 위도 -90~90, 경도 -180~180, 유한 숫자, 정확도는 NULL 또는 0 이상, 측정 시각은 ISO 8601로 검증한다.
- 신규 메시지 생성은 서버 기준 5분 이내 측정 결과와 미래 시각 오차 최대 1분을 초기 허용치로 제안한다. 측정 진위를 인증하는 기능으로 사용하지 않는다.
- 인증·현재 여행/파티 멤버십을 검사한 뒤 멱등 재전송을 찾는다. 새 메시지를 생성하는 경우에 공유 설정·여행 활성 상태·측정 시각을 검증한다. 재시도 때문에 기존 메시지의 측정 시각을 새로 만들지 않는다.
- 멱등 digest에는 여행·파티·좌표·정확도·원래 측정 시각을 포함한다. 전송 실패 후 재시도는 같은 본문·키를 사용한다. `다시 측정` 또는 새 공유에는 새 키를 발급한다.
- 멱등 저장소에는 좌표가 든 전체 응답 대신 메시지 ID를 저장하고, 재시도 응답은 현재 메시지를 재조회한다. 공유 철회 이후 재시도로 좌표가 다시 노출되지 않도록 한다.
- 응답은 기존 `ChatMessage` 필드를 유지하고 `location: { latitude, longitude, accuracyM, capturedAt, revokedAt } | null`을 추가한다. 지도 URL은 DB에 저장하지 않고 표시할 때 요청한다.
- 철회된 카드에는 `kind: LOCATION`과 `revokedAt`을 유지하되 좌표·정확도는 NULL로 반환한다. 철회는 반복 호출해도 같은 상태다.
- 다른 방의 메시지 ID로 지도나 좌표를 조회할 수 없게 이력·단건·지도 URL·철회 API 모두에서 동일한 방 범위를 확인한다.
- 미리보기 URL 발급도 인증·현재 방 멤버십·여행 활성 상태·위치 공유 설정을 검사한다. 좌표를 저장하지 않는 API도 무인증 지도 URL 발급기로 열어 두지 않는다.
- 요청 본문·좌표·서명 URL을 일반 접근 로그·오류 로그에 남기지 않는다. 미리보기/지도 URL 발급에는 사용자별 요청 제한을 둔다.

## 5. DB 변경안

신규 **`chat_location` 테이블 한 개**를 제안한다. 위치는 여행 멤버의 최신 상태가 아닌 메시지 한 건에 귀속된다.

| 필드 | 제안 타입/제약 | 목적 |
| --- | --- | --- |
| `message_id` | BIGINT PK, `chat_message(id)` FK, ON DELETE CASCADE | 위치 메시지당 1건 |
| `latitude`, `longitude` | DECIMAL(10,7), 철회 시 NULL | 공유한 좌표 |
| `accuracy_m` | DECIMAL(10,2) NULL | 기기가 보고한 정확도 |
| `captured_at` | DATETIME(6) NOT NULL, UTC | 실제 측정 시각 |
| `revoked_at` | DATETIME(6) NULL, UTC | 작성자의 공유 철회 시각 |

- 서버 수신·공유 시각은 기존 `chat_message.created_at`을 사용한다. 멤버의 위치 이력·추적 세션 테이블은 만들지 않는다.
- 활성 행의 위도·경도는 모두 존재하고 범위가 유효하도록 CHECK 제약을 둔다. 철회 행은 좌표·정확도가 모두 NULL이 되도록 한다.
- 이력 조회는 기존 `idx_chat_history(trip_id, party_id, id)`와 `chat_location` PK 조인을 활용한다. 거리 검색이 없으므로 공간 인덱스는 첫 버전에 추가하지 않는다.
- 기존 코드와 011 마이그레이션/로컬 DDL 기록에서 `chat_message.kind`는 VARCHAR(10)이며 `LOCATION`은 들어간다. 레거시 `message_type`을 위치 분류에 사용하지 않는다.
- [016-chat-location.sql](../backend/db/migrations/016-chat-location.sql)을 적용하기 전에 대상 DB의 `SHOW CREATE TABLE chat_message`와 기존 CHECK 제약을 확인한다. 적용 기록은 [구현 및 실행 안내](CHAT-LOCATION-IMPLEMENTATION.md)에 남긴다.
- 메시지와 위치 행 생성에 실패하면 둘 다 롤백한다. 기존 채팅을 변환하거나 좌표를 자동 보충하지 않는다.

## 6. 기존 채팅 기능과 연결

- `ChatService`의 전체/파티 권한 검사, 서버 시각, 멱등성, `Changed` 이벤트, 푸시 큐를 재사용한다. 위치 메시지 저장 커밋 후 기존 `/ws/chat` 변경 신호로 수신자가 메시지를 다시 조회한다.
- 프런트엔드 `ChatApi`, `ChatMessage`, `chat-context.tsx` 생성 분기에 `LOCATION`을 추가한다. 기존 방별 쓰기 잠금·요청 세대·메시지 병합·스크롤 동작에 포함한다.
- 위치 DTO를 이력 조회 메시지마다 추가 쿼리로 읽지 않도록 조인 또는 페이지 단위 일괄 조회를 사용한다. 지도 이미지는 화면에 보이는 카드에 한해 지연 로딩하고, 응답·이미지 갱신으로 채팅 위치가 튀지 않도록 카드 크기를 예약한다.
- 지도 URL 발급·재시도는 GPS 측정이나 새 메시지 생성을 유발하지 않는다. 다른 사람의 카드를 열어도 수신자의 위치 권한을 요청하지 않는다.
- 철회 시 `revision`을 증가시키고 기존 `Changed` 이벤트로 전달한다. 지도 URL 응답도 메시지 revision에 연결하고, 철회·방 전환 뒤 늦게 도착한 URL을 카드에 다시 붙이지 않는다. 구버전용 `text`도 `위치 공유가 취소되었어요.`로 갱신한다.
- `이미지만 보기`는 기존 IMAGE 메시지만 표시한다. 위치 카드를 사진 앨범 필터에 섞지 않는다.
- `ChatPushPolicy`에는 `LOCATION → 위치를 공유했어요.`를 추가한다. 푸시 본문·데이터에는 좌표나 지도 URL을 넣지 않는다. 기존 멤버십·수신 설정 검사를 따른다.
- 신규 카드 렌더러는 `LOCATION`을 우선 처리한다. 구버전 앱의 빈 말풍선을 막기 위해 서버의 `text`에는 `위치를 공유했어요. 최신 앱에서 지도를 확인해 주세요.`라는 호환 문구를 둔다. 최신 UI는 카드와 호환 문구를 중복 표시하지 않는다.
- DB 준비 → 서버 DTO/API 배포 → 위치 모듈이 포함된 새 앱 배포 → 기능 노출 순서로 진행한다.

## 7. 공유·보관 정책의 권장 기본값

| 항목 | 이번 계획의 기본값 |
| --- | --- |
| 공개 범위 | 선택한 전체/파티 채팅의 기존 이력 접근 정책. 조회 시점의 멤버 권한 검사 |
| 수집 시점 | 사용자의 내 위치/다시 측정 동작에서 1회 |
| 공개 시점 | 미리보기에서 이 위치 보내기를 눌러 저장에 성공한 때 |
| 보관 | 일반 채팅 이력과 함께 유지. 이전 계획의 1시간 자동 만료는 적용하지 않음 |
| 재공유 | 기존 카드를 이동시키지 않고 새 LOCATION 메시지 생성 |
| 계정의 위치 공유 설정 OFF | 신규 측정·공유 차단. 이미 보낸 카드를 자동 삭제하지 않음 |
| 로그아웃 | 진행 중인 미리보기 폐기. 이미 보낸 채팅은 유지 |
| 작성자의 공유 철회 | 카드 메뉴에서 좌표·정확도를 제거하고 철회 안내 표시 |
| 계정 삭제 | 작성자 연결이 NULL로 바뀌기 전에 해당 계정의 위치 좌표를 철회·정리 |
| 보관된 여행 | 새 위치 전송 차단. 기존 이력 조회와 작성자의 위치 철회 허용 |
| 여행/메시지 삭제 | 기존 메시지 삭제 수명에 맞춰 위치 행도 CASCADE 정리 |

이 표는 구현 계획의 제안 기본값이다. 위치 공유 설정 OFF 안내에는 `새 위치 공유를 중지합니다. 이미 보낸 위치는 해당 메시지에서 공유를 취소할 수 있습니다`를 표시해 동작을 분명하게 한다. 기존 계획의 설정 OFF·로그아웃 시 최신 좌표 자동 제거 정책은 채팅 메시지 방식으로 전환하면서 위 정책으로 대체한다.

## 9. 구현 순서와 완료 기준

| 순서 | 작업 | 완료 기준 |
| --- | --- | --- |
| 1 | 정책·API·DB 계약과 지도 키/서명 구성 확정 | 공유 대상·보관·철회·구버전 표시를 일관되게 정의 |
| 2 | DB 마이그레이션과 서버 LOCATION 메시지 | 가짜 좌표로 생성·조회·철회·멱등성·권한 검증 |
| 3 | Google 서명 URL 발급 | 미리보기·메시지별 직접 표시, 임의 URL 중계 차단 |
| 4 | 플랫폼별 단발 위치 측정·미리보기 | 권한·취소·시간 초과·재측정·방 전환 처리 |
| 5 | 지도 카드·전송·소켓·푸시 통합 | 두 계정에서 올바른 방에 1건 표시, 기존 사진·투표 정상 |
| 6 | 새 APK와 웹 실기기 확인 | 핀 좌표·측정 시각·정확도·지도 열기·철회까지 확인 |

필수 검증은 다음과 같다.

- 내 위치 아이콘 선택 전 GPS 측정이 없고, 취소·권한 거절·지도 미리보기 실패에는 메시지가 생성되지 않는다.
- 전송은 현재 선택한 전체/파티 채팅에만 도착하고, 다른 여행/파티 사용자는 좌표·지도 URL·철회 API에 접근할 수 없다.
- 빠른 중복 탭과 응답 유실 후 재시도로 메시지·푸시가 중복 생성되지 않는다. 재시도 시 원래 측정값·측정 시각을 유지한다.
- 방 전환·계정 변경·백그라운드 전환 후 늦게 끝난 측정이 다른 방이나 계정으로 전송되지 않는다.
- LOCATION 생성과 좌표 저장은 함께 성공하거나 함께 롤백된다. 자동 검증은 고정된 가짜 좌표를 사용한다.
- 지도에 표시한 핀과 전송 DTO·DB·Google 지도 열기의 좌표가 같고, 과거 카드는 이동 후에도 원래 지점을 표시한다.
- 공유 철회 후 재조회·재접속·멱등 재시도로 좌표가 다시 나타나지 않는다. 이미 로드한 다른 기기도 revision 이벤트로 카드를 갱신한다.
- 작성자 계정 삭제 시 좌표 정리가 작성자 ID NULL 처리보다 먼저 이루어진다.
- 위치 카드는 사진 필터에 포함되지 않고, 기존 텍스트·사진·투표·메시지 그룹·스크롤·푸시 이동이 유지된다.
- Google 지도 실패·할당량 오류 시 오류 카드와 재시도가 보이며, 지도 로딩만으로 새 위치를 측정하지 않는다.
- API 키 제한·서명·서명 비밀 비노출·로그 마스킹·Google 로고 보존을 확인한다. 앱 전용 키와 웹 전용 키의 동작은 실제 배포 환경에서 각각 확인한다.
- Android/iOS 권한과 웹 HTTPS 환경을 확인하고, 앱을 닫거나 기기를 이동해도 추가 측정·전송이 없는지 확인한다.

실제 배포 환경에서 지도 키 설정과 실기기 GPS 확인을 마친 후 위치 공유를 사용한다.
