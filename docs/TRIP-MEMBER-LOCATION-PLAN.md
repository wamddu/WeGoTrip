# 여행 멤버 위치 수동 동기화 구현 계획

> 기준일: 2026-10-27 · 사용자 요청에 따라 수동 동기화 방식으로 계획 수정 · 앱 코드·의존성·실제 DB 변경 및 위치 수집은 수행하지 않음

## 1. 핵심 동작

**멤버가 `내 위치 동기화` 버튼을 눌렀을 때만 현재 위치를 한 번 측정해 선택한 여행에 공유한다.** 다시 누르기 전까지 위치를 새로 수집하거나 전송하지 않는다.

지도에 보이는 것은 계속 추적한 현재 위치가 아니라 **각 멤버가 마지막으로 공유한 위치**다. 이름과 공유 시각을 항상 함께 표시한다.

| 동작                      | GPS 측정·업로드                 | 서버 위치 조회                       |
| ------------------------- | ------------------------------- | ------------------------------------ |
| 내 위치 동기화            | 본인 위치를 한 번 측정해 업로드 | 성공 후 지도 갱신                    |
| 지도 새로고침             | 하지 않음                       | 멤버들이 마지막으로 공유한 위치 조회 |
| 다른 멤버가 동기화        | 내 위치를 측정하지 않음         | 열린 지도에 변경 반영                |
| 지도 진입·앱 복귀         | 하지 않음                       | 최신 공유 목록만 조회                |
| 화면 이동·앱 종료·탭 숨김 | 추가 수집·전송 없음             | 이미 공유한 점은 유효기간 동안 유지  |

자동 추적, 주기적 위치 전송, 이동 거리 감지, 백그라운드 수집은 이번 범위에서 제외한다. 위치 표시를 위해 백그라운드 권한이나 지속 알림을 요구하지 않는다.

## 2. 화면 구성과 공유 정책

여행 화면에 **멤버 위치** 화면을 추가한다.

- `내 위치 동기화`: 위치 권한 확인 → 한 번 측정 → 서버 저장.
- `지도 새로고침`: 본인 GPS를 사용하지 않고 공유 목록만 다시 조회.
- `내 위치 공유 해제`: 해당 여행에 남아 있는 본인 좌표를 제거.
- `전체 보기`, `내 공유 위치 보기`: 이미 저장된 좌표로 지도만 이동.
- 마커와 멤버 목록에 `지우 · 14:05 공유 · 12분 전`처럼 표시.
- 정확도가 낮으면 정확도 원과 `대략적인 위치` 안내 표시.
- 동기화 중 중복 누름 방지와 권한 거절·측정 실패·통신 오류 안내.

| 항목        | 제안                                                                          |
| ----------- | ----------------------------------------------------------------------------- |
| 공개 범위   | 버튼을 누른 여행의 현재 멤버 전체                                             |
| 본인 제어   | 본인만 좌표 동기화·공유 해제 가능. 방장도 다른 멤버 위치를 갱신할 수 없음     |
| 여러 여행   | 사용자가 각 여행에서 직접 동기화한 경우에만 해당 여행에 공유                  |
| 계정 설정   | 기존 위치 공유 설정을 전송 허용·차단에 사용. 설정 ON만으로 좌표를 보내지 않음 |
| 조회 권한   | 내 위치를 공유하지 않아도 같은 여행의 공유된 위치는 조회 가능                 |
| 오래된 위치 | 항상 마지막 공유 시각을 표시. 예를 들어 5분 경과 시 흐린 마커로 구분          |
| 보관 시간   | 마지막 동기화 후 1시간 자동 숨김을 초기값으로 제안. 구현 전 확정              |
| 공유 종료   | 직접 해제, 계정 설정 OFF, 로그아웃, 여행 탈퇴·종료, 유효기간 만료             |
| 저장 범위   | 여행 멤버별 최신 공유 좌표 1건. 이동 경로·누적 이력은 저장하지 않음           |

조회·새로고침·재접속은 위치 시각이나 유효기간을 연장하지 않는다. 같은 장소에서 다시 동기화해도 새 측정이 성공했다면 새로운 공유 시각으로 갱신한다. 위치 공유에는 푸시 알림 권한이 필요하지 않다.

## 3. 단발 위치 측정

| 플랫폼      | 사용할 API                                   | 처리                                                        |
| ----------- | -------------------------------------------- | ----------------------------------------------------------- |
| Android/iOS | `expo-location.getCurrentPositionAsync()`    | 버튼을 누른 시점에 foreground 권한을 확인하고 위치 1회 측정 |
| 웹          | `navigator.geolocation.getCurrentPosition()` | 사용자 권한 및 HTTPS/localhost 환경에서 위치 1회 측정       |

Expo는 현재 위치의 단발 측정을 지원한다. [Expo SDK 57 Location](https://docs.expo.dev/versions/v57.0.0/sdk/location/#locationgetcurrentpositionasyncoptions)
웹도 단발 조회 API를 사용하고, `maximumAge: 0`과 적절한 제한 시간을 적용한다. [웹 Geolocation 문서](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/getCurrentPosition)

```text
사용자가 내 위치 동기화 선택
→ 공유 대상 여행·계정 설정 확인
→ 위치 권한 확인·필요 시 요청
→ 현재 위치 한 번 측정
→ 인증된 API로 본인 좌표 저장
→ 내 지도 갱신 및 다른 멤버에게 변경 전달
```

- 오래된 마지막 위치를 가져와 새로 측정한 것처럼 공유하지 않는다.
- 측정·전송 실패 시 오류를 안내한다. 이전 공유 위치가 있으면 원래 시각 그대로 유지한다.
- 위치 측정에는 제한 시간을 두고 늦게 도착한 결과를 무시한다.
- 측정 중 화면 이탈·로그아웃·계정 변경·공유 해제가 발생하면 이후 업로드를 취소한다.
- 앱 안에 상시 GPS 감시 Provider를 두지 않는다. 수동 동기화 요청과 지도 조회 상태만 관리한다.

## 4. 서버와 다른 멤버에게 반영하는 방식

**좌표를 올리는 동작은 수동으로, 다른 멤버가 올린 좌표를 받는 동작은 자동으로 처리한다.**

```text
내 위치 동기화 → HTTP 저장 → 커밋 후 위치 변경 이벤트
→ 같은 여행의 열린 지도에서 공유 목록 재조회 → 마커 갱신
```

- 채팅의 인증·Origin 제한·재접속 패턴을 재사용한 `/ws/locations` 채널을 제안한다.
- 소켓은 멤버 위치 화면이 활성화된 동안만 연결한다.
- 이벤트는 좌표 대신 `locations.changed` 같은 변경 신호를 전달한다. 수신자는 인증된 HTTP API로 목록을 다시 읽는다.
- 수동 갱신이므로 주기적 좌표 전송·고빈도 방송·상시 위치 세션은 필요하지 않다.
- 소켓을 사용할 수 없으면 지도 진입·복귀·새로고침으로 최신 목록을 확인할 수 있다.
- 권한·여행 멤버십은 조회·쓰기·소켓 구독·이벤트 전달 시 서버에서 검사한다.
- 본인 위도·경도를 다른 멤버가 대신 입력하지 못하도록 송신자는 JWT로 확정한다.
- 중복 이벤트·역전된 HTTP 응답을 무시하고, 위치 조회 때문에 전체 여행 Workspace를 다시 불러오지 않는다.
- 위치 갱신마다 채팅 메시지나 푸시 알림을 만들지 않는다.

### API 초안

기본 경로: `/api/v1/trips/{tripId}/locations`

| 요청          | 역할                                                                 |
| ------------- | -------------------------------------------------------------------- |
| GET 기본 경로 | 유효한 공유 위치 목록, 공유 시각·정확도, 본인 멤버 ID·수정 버전 반환 |
| PUT `/me`     | 버튼으로 측정한 본인 위도·경도·정확도·측정 시각 저장                 |
| DELETE `/me`  | 해당 여행의 본인 공유 좌표 제거                                      |

PUT·DELETE에는 UUID `Idempotency-Key`와 멤버 ID·`expectedVersion`을 사용한다. 응답 유실 재시도는 같은 요청으로 처리하며 좌표·공유 시각·유효기간을 다시 갱신하지 않는다. 다음 버튼 누름은 새 측정과 새 요청 키를 사용한다.

멤버 ID·버전으로 다른 기기의 늦은 저장이나 탈퇴 전 요청이 새로운 공유를 덮어쓰는 것을 막는다. 공유 해제 후 늦게 도착한 요청도 이전 위치를 다시 공개하지 못하게 한다. 좌표 범위·정확도·측정 시각을 검증하며 유효기간은 서버 시각으로 판단한다.

## 5. DB 변경 초안

기존 DB에서 위치 공유 허용 설정은 확인했지만 최신 공유 좌표를 보관할 테이블은 없었다. **`trip_member_location` 테이블 1개**를 신규 제안한다.

| 필드                                  | 목적                                                   |
| ------------------------------------- | ------------------------------------------------------ |
| `trip_member_id` PK·FK                | 여행 멤버별 최신 공유 정보 1건. 멤버 삭제 시 함께 정리 |
| `latitude`, `longitude`, `accuracy_m` | 마지막 공유 좌표·정확도. 공유 해제 시 NULL로 정리      |
| `captured_at`, `received_at`          | 측정 시각과 서버 수신 시각 구분                        |
| `expires_at`                          | 마지막 공유 위치의 표시 유효기간                       |
| `version`                             | 동시 동기화·공유 해제·지연 요청 충돌 검사              |
| `publisher_token_version`             | 기존 로그아웃·인증 무효화와 연결                       |

공유 해제·만료 시 좌표를 비우고 버전을 증가시켜 지연 요청의 재공개를 막는다. 좌표가 없는 최소 상태는 충돌 검사용으로 유지하고 멤버 삭제 시 행도 정리한다. 별도 추적 세션·기기 임대·연속 측정 순번은 추가하지 않는다.

계정 설정 OFF·로그아웃·여행 탈퇴·종료에도 서버에서 좌표를 숨기고 정리한다. 일반 로그·기기 영구 저장소에 좌표를 남기지 않고 API 응답은 캐시하지 않는다.

**실제 구현 시 정확한 SQL·인덱스·외래키 변경안을 제시하고 승인받은 뒤 적용한다. 이번 계획 수정에서는 실제 DB를 변경하지 않았다.**

## 6. 지도와 기존 코드 활용

- 기존 `GeographicMap`의 지도 배경·좌표 투영을 재사용한다.
- 멤버 위치가 바뀌어도 배경 지도를 매번 다시 요청하지 않도록 마커와 카메라 상태를 분리한다.
- 첫 진입·`전체 보기`·멤버 선택 때 화면을 맞추고, 이후 사용자가 이동한 카메라는 유지한다.
- 따라가기 모드는 제공하지 않고 `내 공유 위치 보기`로 마지막 공유점을 보여 준다.
- Google 로고·저작권 표시를 가리지 않는다.

Static API는 요청 URL로 지도 이미지를 생성한다. [Google Maps Static API](https://developers.google.com/maps/documentation/maps-static/overview)

## 7. 구현 순서와 완료 기준

| 순서 | 작업                                      | 완료 기준                                              |
| ---- | ----------------------------------------- | ------------------------------------------------------ |
| 1    | 수동 공유 정책·보관 시간·API·DB 계약 확정 | 자동 추적 없이 동작하는 계약과 승인된 SQL 준비         |
| 2    | 저장·조회·공유 해제·만료 API              | 본인만 갱신, 현재 멤버만 조회, 중복·지연 요청 처리     |
| 3    | 앱·웹 단발 위치 어댑터                    | 버튼을 누를 때만 측정, 권한·제한 시간·취소 처리        |
| 4    | 멤버 위치 화면                            | 동기화·새로고침·해제 버튼과 공유 시각·정확도 표시      |
| 5    | 변경 이벤트와 지도 갱신                   | 다른 멤버의 열린 지도에 수동 동기화 결과 반영          |
| 6    | 통합·실기기 검증                          | 두 기기에서 공유·해제·오류·권한 및 자동 수집 없음 확인 |

예상 파일은 서버 `LocationController`, `LocationService`, `LocationSocket`, 만료 정리 작업과 프런트엔드 `member-location-api`, 플랫폼별 단발 위치 어댑터, `useLocationSync`, `member-location-screen`이다.

### 필수 검증

- 로그인·화면 진입·새로고침·앱 복귀만으로 GPS 측정이나 좌표 업로드가 발생하지 않는지.
- 동기화 버튼 한 번에 위치 1회 측정과 저장 요청 1건만 발생하는지.
- 같은 위치를 다시 동기화하면 실제 새 측정 결과와 새 공유 시각이 반영되는지.
- 권한 거절·측정 실패·전송 실패 시 이전 공유 시각을 바꾸지 않는지.
- 다른 멤버의 동기화가 내 GPS 측정을 유발하지 않고 지도에 반영되는지.
- 공유 해제·계정 설정 OFF·로그아웃 후 지연 요청으로 좌표가 재공개되지 않는지.
- 비멤버·탈퇴한 멤버의 조회와 다른 사람의 위치 수정이 차단되는지.
- 앱을 닫거나 기기가 이동해도 버튼을 다시 누르기 전에는 추가 전송되지 않는지.
- 만료된 위치가 숨겨지고, 목록 조회로 만료 시간이 연장되지 않는지.
- 가짜 좌표 기반 자동 검증 후 실제 휴대폰 2대 이상에서 권한·정확도·공유 시각을 확인하는지.
