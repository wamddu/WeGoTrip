# 검증 기록

검증일: 2026-09-09. Windows에서 진행했으며 브라우저는 React Native Web 실행 결과다.

## 자동 검사

- `npm test`: 도메인 및 데이터 어댑터 테스트 22개 통과(지도 관련 6개 포함).
- `tsc --noEmit --noUnusedLocals --noUnusedParameters`: 통과.
- Expo export: 웹, Android Hermes, iOS Hermes 번들 생성 통과.
- `git diff --check`: 공백 오류 없음.

## 브라우저에서 실행한 흐름

1. 샘플 계정 로그인 → 홈 → 부산 여행 → 날짜별 일정.
2. 카페 파티 선택 시 해당 파티와 공통 일정만 표시. 공통 일정을 편집해도 파티 소속이 바뀌지 않음.
3. 일정 메모 수정 → 저장 → 서버/브라우저를 다시 열어 수정 내용과 로그인 복원 확인.
4. 파티 지출 추가 시 해당 파티의 2명이 부담 멤버 기본값으로 선택됨.
5. 10,001원 지출에 6,000+4,000원 직접 분담을 입력하면 합계 오류. 6,000+4,001원으로 고치면 저장되고 총 지출 594,001원 및 정산 계획에 반영됨.
6. 준비물 완료 → 진행률 2/5에서 3/5로 변경, 다른 계정에서도 같은 로컬 저장 내용 확인.
7. 그룹 메시지 작성 → 메시지와 작성 시간 표시. 공지 고정 항목이 대화방에 노출됨.
8. 새 로컬 프로필 가입 → 빈 여행 홈 → BUSAN26 코드로 기존 여행 참여 → 멤버 수 4명에서 5명으로 변경.
9. 새 강릉 여행 생성 → 멤버 직접 초대 → 장소 등록 → 장소를 연결한 일정 추가 → 날짜별 동선에 방문 순서 표시.
10. 공지 작성·고정 → 다른 멤버로 로그인 → 알림 목록 → 해당 여행 공지 화면으로 이동.

390×844 및 320×740 크기로 홈, 여행 개요, 일정/정산 입력, 가입/여행 생성 화면을 확인했다. 320px에서 예산 카드를 한 열로 배치해 금액이 잘리지 않게 조정했다. 입력 화면에서는 하단 메뉴를 숨기며, 긴 내용은 스크롤할 수 있다. 전체 문서에 가로 넘침이 없음을 확인했다.

브라우저 검증 중 입력한 데이터는 해당 브라우저의 로컬 저장소에만 남는다. 버전 관리하는 fixture에는 테스트 입력을 넣지 않았다.

## 휴대폰 이미지 잘림 수정 검증

로그인, 홈/내 여행 카드, 여행 개요의 고정 높이와 기본 `cover` 확대 표시를 공통 `TravelCover`로 교체했다. 실제 컨테이너 크기를 측정하고 원본 비율로 최소 높이를 계산하며 `contain`으로 이미지 전체를 표시한다. 텍스트가 길어지면 컨테이너가 늘어나고, 로그인 패널의 음수 여백도 제거해 이미지 하단을 가리지 않는다.

브라우저의 실제 CSS 너비 320px와 390px에서 로그인, 홈, 여행 개요의 이미지 표시와 가로 넘침 없음을 확인했다. 너비 변경 후 이미지 크기가 갱신되며, 넓은 화면에서는 앱의 최대 너비 500px를 따른다. 타입 검사, Prettier 검사, 웹/Android/iOS Expo export 및 `git diff --check`를 통과했다. 실기기에서의 재검증은 하지 않았다.

## 일정 동선 지도 검증

- 날짜·파티 필터, 공통 일정 포함, 다른 파티 사이 연결 금지, 누락 좌표/겹친 시간의 연결 중단, 같은 장소 재방문 순서를 테스트했다.
- 좌표 형식·범위·빈 값 검증, 기존 샘플 좌표 보완 시 사용자 수정 보존, 좌표 저장 후 새 저장소 인스턴스에서 복원, 지도 투영과 화면 맞춤, 날짜 변경선·극지 타일 범위를 검사했다.
- 브라우저에서 실제 OpenStreetMap 타일 로드, 부산 일정의 번호·점선, 파티 전환, 마커 선택, 확대·축소·전체 보기, 위치 미등록 안내와 장소 수정 연결을 확인했다. 위치 선택 시 좌표 입력, 잘못된 좌표 저장 거절도 확인했고 해당 폼의 테스트 입력은 저장하지 않았다.
- 실제 CSS 너비 320px와 390px에서 지도와 제어 버튼의 배치 및 가로 넘침 없음을 확인했다.
- 웹/Android/iOS Expo export와 TypeScript 검사를 통과했다. 네이티브 설치·터치 동작은 실제 기기에서 확인하지 않았다.

## 검증 범위의 한계

Android prebuild는 성공했지만 APK 생성은 실패했다. Windows 프로젝트 경로에 한글이 있어 Android Gradle Plugin의 경로 검사에서 거절되었고, 생성된 `android/gradle.properties`에 `android.overridePathCheck=true`를 적용한 뒤에도 `react-native-worklets` CMake/Clang 단계에서 한글 경로가 깨져 `WorkletsPCH.h`를 열지 못했다. 따라서 APK 빌드 성공으로 보고하지 않는다. SDK 36, Build Tools 36, NDK 27.1, CMake 3.22.1 설치까지 진행했다. 영어/숫자로 된 경로에 프로젝트와 의존성을 설치한 뒤 네이티브 빌드를 다시 검증해야 한다. 원본 프로젝트 경로는 변경하지 않았다.

실제 인증 서버와의 통신은 진행하지 않았다. HTTP 어댑터는 가짜 fetch 응답으로 계약을 검증했다. 외부 지도 서비스 결과, 공유 앱으로 실제 발송, 기기 간 실시간 메시지·푸시·GPS·OCR은 검증 대상이 아니다. 연결된 Android 실기기/에뮬레이터는 없으며 iOS 설치 검증도 진행하지 않았다.
