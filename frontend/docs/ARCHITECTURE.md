# WeGoTrip 앱 구조

계획서의 여행 그룹·파티·일정·장소·공동 경비·준비물·공지·채팅을 하나의 여행에 연결했다. 컨셉 아트의 파랑/민트 색감, 여행 커버, 밝은 카드와 메뉴 느낌을 반영했다. 화면 구성안의 메뉴 배치는 제안으로 참고했으며 기능의 기준은 계획서다.

## 계층과 데이터 흐름

```text
src/app/                 Expo Router 인증/여행/편집 경로
src/features/            로그인, 홈, 여행 기능 화면
src/ui/                  색상, 아이콘, 버튼, 입력, 공통 화면 프레임
src/state/               세션·데이터·저장 상태와 중복 저장 방지
src/domain/models.ts    엔티티, 명령 타입, 날짜/정산 계산
src/domain/commands.ts  변경 검증과 로컬 도메인 규칙
src/data/contracts.ts  TravelRepository, KeyValueStorage 인터페이스
src/data/repository.ts 환경변수에 따른 저장소 선택
src/data/mock-repository.ts 로컬 데이터 어댑터
src/data/http-repository.ts HTTP 데이터 어댑터
src/data/fixtures/workspace.ts 모든 예시 사용자/여행/지출/메시지
```

화면 → `useTravel().execute(command)` → 저장소 → 새 Workspace → 공통 상태 → 관련 화면 갱신. 화면은 fixture를 직접 참조하지 않는다. 저장이 성공한 이후 화면을 갱신하며 실패한 폼의 입력은 유지한다. 재조회 중 저장을 시작하면 오래된 조회 결과가 최신 상태를 덮지 않도록 조회 버전을 검사한다.

현재 저장소는 여행 규모의 Workspace를 통째로 조회한다. 대규모 사용 시 같은 계층 경계를 유지하면서 여행별 조회, 채팅 페이지네이션, 서버 이벤트 구독을 추가할 수 있다. 현재 메시지와 목록은 유한한 로컬 데이터 기준이며 무한 스크롤 구현은 포함하지 않는다.

## 구현한 기능

| 기능      | 현재 동작                                                                                       |
| --------- | ----------------------------------------------------------------------------------------------- |
| 인증 화면 | 로그인·회원가입, 오류 처리. 로컬 모드는 이메일 기반 프로필 선택/생성, HTTP 모드는 비밀번호 전달 |
| 여행      | 생성, 친구 선택, 초대 코드 참여, 여행장 직접 초대, 기본 정보 수정, 종료/다시 열기               |
| 친구·멤버 | 이름/이메일 검색, 로컬 친구 등록, 여행 멤버 목록                                                |
| 파티      | 이름·멤버·활동 날짜/시간 생성/수정/삭제                                                         |
| 일정      | 날짜별 시간순 표시, CRUD, 저장 장소 연결, 공통/파티 필터                                        |
| 장소      | 주소·분류·메모 저장/수정/삭제, 검색, 일정에 추가, 날짜별 방문 순서, 외부 지도 열기              |
| 경비·정산 | 결제자·부담 대상·날짜·메모, 균등/직접 분담, 송금 대상/금액 계산, 완료 기록                      |
| 준비물    | 공용/담당자, 추가·수정·삭제·완료, 전체/내 준비물/미완료 필터                                    |
| 공지      | 작성·수정·삭제·고정, 작성자/여행장 권한 검사                                                    |
| 대화·알림 | 여행 채팅 작성/보존, 날짜별 말풍선, 다른 멤버의 변경 알림과 관련 화면 이동                      |

실제 인증 서버, 기기 간 실시간 협업·푸시 알림, 장소 검색/도로 길찾기 API, OCR 영수증 인식, GPS 공유, AI 여행 도우미는 아직 연결하지 않았다. 일정 지도는 온라인 타일 위에 저장한 좌표와 방문 순서 점선을 표시한다. 장소 수정에서 지도로 위치를 선택하거나 좌표를 입력할 수 있으며 주소 기반 외부 지도 열기도 유지한다. 송금 완료는 사용자의 수동 기록이며 금융 송금을 실행하지 않는다.

## 도메인 규칙

- 여행장만 기본 정보와 직접 멤버 초대를 관리한다. 초대 코드는 여행에 참여할 권한을 부여한다.
- 일정 날짜는 여행 기간 내, 파티 일정은 해당 파티의 활동 날짜/시간 내여야 한다. 파티 필터에도 공통 합류 일정을 표시한다.
- 파티 선택은 새 지출의 부담 멤버 초기값만 채운다. 이후 파티 변경은 기존 지출의 분담액을 바꾸지 않는다.
- 금액은 원 단위 정수다. 분담 합계는 지출액과 정확히 같아야 한다. 균등 분할 잔액은 여행 멤버 순서로 1원씩 배분한다.
- 송금 계획은 결제액−부담액을 상계한다. 지출 변경 시 기존 완료 기록을 초기화하고 다시 확인하도록 안내한다.
- 참조 중인 장소/파티 삭제와 다른 사람의 공지 수정은 거절한다. 메시지 작성자는 로그인 사용자로 확정한다.
- 종료한 여행은 내용 편집이 제한된다. 정산 완료 기록은 종료 후에도 가능하다.

## 저장과 인증

웹은 localStorage, Android/iOS는 `expo-file-system`의 앱 문서 디렉터리를 사용한다. 초기 데이터가 없을 때만 fixture를 복제한다. fixture 파일을 수정해도 이미 저장된 사용자 데이터를 덮지 않는다.

좌표 추가 시에는 `src/data/migrations.ts`에서 여행 ID·장소 ID·이름·주소가 모두 일치하는 기존 샘플 장소의 누락된 좌표만 보완한다. 사용자가 수정한 장소와 명시적으로 지운 좌표(`null`)는 보존한다. 자세한 지도 계층과 정책은 [MAPS.md](MAPS.md)에 기록했다.

로컬 파일: `wegotrip-workspace-v1.json`, `wegotrip-local-session.json`. 웹 키: `wegotrip-workspace-v1`, `wegotrip-local-session`. 초기화가 필요하면 해당 브라우저의 사이트 데이터를 지우거나 앱 데이터를 초기화한다. 기존 입력 데이터도 함께 사라진다.

로컬 프로필은 UI와 데이터 흐름 개발용이며 보안 인증이 아니다. 비밀번호를 저장하지 않는다. HTTP 어댑터의 access token은 메모리에만 보관하여 앱을 다시 켜면 로그인해야 한다. 서비스 운영 전 서버 인증/인가, 안전한 refresh token 저장, 계정 복구, 서버 트랜잭션과 충돌 처리가 필요하다. 클라이언트 도메인 검사는 서버 권한 검사의 대체물이 아니다.

## 검사

`npm test`는 날짜/금액 검증, 정산 보존, 권한, 초대, 파티 시간, 참조 삭제 제한, 알림, 입력 불변성, 로컬 저장 복원·동시 저장·실패 복구, HTTP 계약을 검사한다. `npm run typecheck`는 전체 UI와 어댑터 타입을 검사한다. 웹 및 Android/iOS export는 번들 생성 검증이며 실제 기기 설치 테스트와 구분한다.

기술 기준: [Expo SDK 57 문서](https://docs.expo.dev/versions/v57.0.0/). 앱 내부 렌더링은 React Native 컴포넌트, 라우팅은 Expo Router를 사용한다. 인증 후 동적 여행 경로이므로 웹 출력은 SPA(`single`)이며 호스팅 시 경로를 index.html로 돌려야 한다.
