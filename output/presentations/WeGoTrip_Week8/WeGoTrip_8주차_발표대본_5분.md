# We Go Trip 8주차 발표 대본

보통 속도로 읽으면 약 5분 분량입니다. 기술 용어는 간단히 설명하고, 작업의 이유와 결과를 중심으로 구성했습니다.

## 1페이지 · We Go Trip

안녕하세요. 10조 We Go Trip의 8주차 진행 내용을 발표하겠습니다.

이번 주에는 서버를 배포하고, 안드로이드 휴대폰에 직접 설치할 수 있는 앱을 만들었습니다. 그리고 실제 앱을 테스트하면서 발견한 문제들을 수정했습니다.

## 2페이지 · GPS 위치 공유 구현을 미룬 이유

원래 이번 주에는 GPS 위치 공유 기능을 구현할 예정이었습니다. 하지만 프로젝트에 기능이 많이 추가되면서, Expo Go뿐만 아니라 실제 설치한 앱에서도 제대로 동작하는지 확인할 필요가 있다고 판단했습니다.

또한 GPS 위치 공유는 여러 기기가 같은 서버에 접속해야 테스트할 수 있습니다. 따라서 이번 주에는 서버 배포와 실제 앱 테스트 환경을 먼저 준비하고, GPS 구현은 다음 주로 미뤘습니다.

## 3페이지 · 프로젝트 일정

전체 프로젝트 일정입니다.

지난주에는 채팅과 투표, 공지 기능을 구현했습니다. 이번 주에는 앞서 설명한 이유로 서버 배포와 APK 테스트를 먼저 진행했습니다.

다음 주에는 이번에 준비한 환경을 활용해 GPS 위치 공유 기능을 구현할 계획입니다.

## 4페이지 · 공동 EC2 서버로 실행 환경 변경

기존에는 개발용 컴퓨터에서 백엔드를 실행했습니다. 이 방식은 해당 컴퓨터의 서버가 켜져 있어야 다른 기기에서도 기능을 사용할 수 있다는 불편함이 있었습니다.

이번에는 AWS의 EC2라는 클라우드 서버로 백엔드를 옮겼습니다. 이제 웹과 앱이 같은 서버에 접속하며, 기존에 사용하던 데이터베이스도 그대로 연결했습니다.

## 5페이지 · JAR 배포와 서버 실행 관리

배포 과정은 크게 세 단계입니다.

먼저 백엔드 코드를 실행 가능한 파일로 만들고, 그 파일을 EC2에 올린 뒤, 서버에서 실행하도록 설정했습니다.

또한 원격 접속 창을 닫아도 백엔드가 계속 실행되도록 했습니다. 오류로 종료되면 다시 시작하고, 서버가 켜질 때 자동으로 실행되도록 설정했습니다.

## 6페이지 · 팀원 접속 주소와 보안 규칙

서버를 옮긴 뒤에는 앱이 요청을 보내는 주소도 변경했습니다. 기존 개발용 주소 대신 EC2 주소를 사용하도록 API와 지도 API 설정을 함께 수정했습니다.

팀원들이 서버에 접근할 수 있도록 접속 규칙을 설정했고, EC2가 데이터베이스에도 연결될 수 있도록 허용했습니다.

이를 통해 여러 기기가 같은 서버와 데이터를 사용하는 환경을 마련했습니다.

## 7페이지 · Firebase 푸시 알림 연결

푸시 알림은 Firebase를 통해 전달하도록 연결했습니다.

사용자가 메시지를 보내면 서버가 알림을 받을 사람을 확인하고, Firebase에 전송을 요청합니다. 그러면 Firebase가 해당 기기에 알림을 전달하는 방식입니다.

이번에는 서버에 필요한 인증 설정을 적용하고, 기기 등록과 알림 수신이 연결되는 것을 확인했습니다.

## 8페이지 · 설치용 Android APK 빌드

다음으로 휴대폰에 직접 설치할 수 있는 APK를 만들었습니다.

APK는 안드로이드 앱의 설치 파일입니다. Expo의 EAS 빌드 서비스를 이용해, 개발 도구에 연결하지 않아도 실행할 수 있는 형태로 제작했습니다.

빌드할 때는 배포한 서버 주소와 Firebase 설정을 적용했습니다. 빌드가 완료되면 APK를 내려받아 휴대폰에 설치하는 방식으로 테스트했습니다.

## 9페이지 · 빌드 설정과 업데이트 설치

수정할 때마다 앱을 삭제하고 다시 설치하지 않도록, 같은 앱으로 인식되는 설정과 서명 키를 유지했습니다. 덕분에 기존 앱 위에 새 버전을 업데이트할 수 있습니다.

처음 테스트용 APK를 만든 뒤, 발견한 문제를 수정하면서 여러 차례 다시 빌드했습니다. 다음 페이지부터는 테스트 과정에서 발견한 주요 문제와 수정 내용을 설명하겠습니다.

## 10페이지 · 사진 업로드 오류 수정

먼저 안드로이드 앱에서 사진을 보낼 때 오류가 발생했습니다.

사진 정보를 전달하는 방식이 앱의 전송 기능과 맞지 않는 것이 원인이었습니다. 이를 해결하기 위해 사진의 위치 정보만 전달하던 부분을, 실제 파일 데이터를 읽어서 전달하도록 수정했습니다.

이후 여러 이미지 형식과 파일 전송 처리를 테스트해 수정 내용을 확인했습니다.

## 11페이지 · 장소 검색 버튼의 터치 영역 수정

장소 검색 버튼은 가운데를 누르면 동작하지만, 양쪽을 누르면 반응하지 않는 문제가 있었습니다.

검색 서버의 응답은 정상이었고, 버튼 상태와 터치 영역을 처리하는 부분에 문제가 있었습니다.

버튼의 활성화 여부를 명확하게 전달하고, 글자뿐 아니라 버튼 전체가 터치를 받도록 수정했습니다. 입력 중이거나 검색 결과를 기다리는 상황도 함께 검사했습니다.

## 12페이지 · 화면 전환 시 하단바 고정

화면을 이동할 때 하단 메뉴가 화면과 함께 움직이는 문제도 수정했습니다.

기존에는 각 화면 안에 하단 메뉴가 들어 있었습니다. 이를 여러 화면이 함께 사용하는 공통 영역으로 옮겨, 화면 내용이 바뀌어도 하단 메뉴는 같은 위치에 있도록 구성했습니다.

작성 화면이나 채팅 화면처럼 하단 메뉴가 필요 없는 곳에서는 숨기도록 처리했습니다.

## 13페이지 · 채팅 진입 위치와 키보드 대응

채팅에서는 방에 다시 들어왔을 때 최신 메시지가 보이도록 스크롤 처리를 수정했습니다. 다만 사용자가 이전 대화를 읽고 있다면, 새 메시지가 와도 읽던 위치가 유지되도록 했습니다.

키보드가 열렸을 때는 입력창이 가려지지 않도록 대화 영역의 높이를 조정했습니다. 연속된 메시지의 이름과 시간 표시도 정리했습니다.

자동 테스트는 통과했으며, 수정된 동작은 실제 안드로이드 기기에서도 추가로 확인할 예정입니다.

## 14페이지 · 내주 계획

다음 주에는 GPS 위치 공유 기능을 구현하겠습니다.

이번 주에 준비한 공동 서버와 설치형 앱을 활용해, 여러 기기가 접속한 상태에서 위치를 공유하고 확인하는 기능을 개발할 계획입니다.

이상으로 발표를 마치겠습니다. 감사합니다.
